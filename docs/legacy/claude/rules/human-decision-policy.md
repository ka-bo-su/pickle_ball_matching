# Human Decision Policy

## 概要

以下の状況では **必ず** 実装・マージを停止し、`status:needs-human` ラベルを付けて人間の判断を仰ぐ。

Claude エージェントは自律的に判断してはいけない。

## 必ず停止するケース

### リスクレベル

- `risk:high` ラベルが付いている
- `risk:critical` ラベルが付いている

### DB 変更

- Breaking DB migration（カラム削除・型変更・テーブル削除）
- DB アクセス制御ポリシーの設計変更・削除
- テナント ID によるデータ分離に影響する変更

### 認証・認可

- 認証ロジックの変更
- 認可・権限チェックの変更
- 認証プロバイダーの設定変更
- admin / staff 権限の変更

### 課金・決済

- 決済プロバイダーの設定・Webhook・価格変更
- 決済方式の変更
- プランの価格変更

### デプロイ・インフラ

- 本番デプロイ workflow の変更
- `.github/workflows/` の変更
- ホスティング / DB プラットフォームの本番設定変更
- `CODEOWNERS` の変更

### 外部サービス

- 新規外部サービスの導入
- 既存外部サービスの認証情報変更
- API キーの変更・ローテーション

### AI・コスト

- AI API のコストが大幅増加する可能性がある変更
- 新規 AI プロバイダーの追加
- プロンプトが大幅に長くなる変更

### データ

- データ保持ポリシーの変更
- データ削除ロジックの変更
- PII（個人情報）の取り扱い変更

### 法的・コンプライアンス

- 利用規約・プライバシーポリシーの変更
- GDPR / 個人情報保護法への対応
- スクレイピング・利用規約センシティブな実装

### セキュリティ

- 顧客データ露出リスクのある変更
- Secret / env の取り扱い変更
- セキュリティ脆弱性の修正（CVE 対応）

## 停止手順

人間判断が必要と判断した場合:

1. 作業を即座に停止する
2. Issue に `status:needs-human` ラベルを付ける
3. Issue / PR に以下のコメントを残す:

```markdown
## 🛑 Human Decision Required

**理由**: [なぜ人間判断が必要か]
**影響範囲**: [何が変わるか]
**リスク**: [何が起きうるか]
**推奨アクション**: [人間に何をしてほしいか]

このIssue/PRは人間の承認まで進めません。
```

4. Orchestrator Claude に通知する
5. 人間の判断を待つ

## 人間が判断すべきこと

人間は以下を判断する:

- 実装を進めてよいか
- リスクを受け入れるか
- 代替アプローチを取るか
- Issue をキャンセルするか
- スコープを変更するか

## 判断後の再開

人間が承認した場合:

1. `status:needs-human` を解除する
2. 承認内容を Issue にコメントとして残す
3. 作業を再開する

## 「あいまいな場合」のデフォルト

判断に迷った場合は **必ず停止して人間に確認する**。

リスクを軽視して進めることは絶対にしない。
